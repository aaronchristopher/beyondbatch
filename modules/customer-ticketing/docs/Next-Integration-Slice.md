# Next integration slice: approved mail to durable request

**Current rollout scope:** [all PM mailboxes](All-PM-Rollout.md), using one shared ingestion service and request database with independently recoverable mailbox/folder jobs. The first single-mailbox connection test below is a technical smoke test only; it does not narrow the approved first operational rollout.

This is the next build sequence once the tenant, hosting scope and permitted mailboxes are known. The production path is not implemented by the local harness. The November 1 continuation adds the credential-independent application transaction contract and conservative reviewed correlation helpers; see `Transaction-Integration.md`. Actual PostgreSQL mapping, identity and live pipeline gates below remain open.

1. **Identity first.** Use a separate production entry point with exclusive UniWell Entra SAML 2.0, enforced MFA and opaque secure server sessions. The former OIDC/bearer proposal is superseded. Resolve current customer/department/evidence grants on every operation; protect direct APIs, downloads and alternate origins. Exclude demo and legacy authentication modules from the production image. Complete [SAML/MFA acceptance](Security-SAML-Access.md) before live content enters the application.
2. **Persist events and outbox atomically.** Apply the reviewed migration to a test database. Build a transaction adapter which locks the request/version, calls the reducer, stores the event and resulting obligations, and writes the outbox entry in one commit. Idempotency keys are tenant-scoped. Verify concurrent replies, crash replay, migration rollback strategy and restore before production.
3. **Connect and verify all approved PM mailboxes.** Obtain application tokens with an approved managed identity or certificate. First smoke-test one approved mailbox, then inventory and baseline every roster mailbox and approved physical folder. Persist incoming and sent copies, per-folder checkpoints, independent retries and coverage state. Prove each included mailbox succeeds and a selected excluded mailbox is denied. Match the application allowlist to the reviewed Microsoft scope. Duplicates across mailboxes retain separate evidence provenance. Verify explicitly included shared-mailbox sent paths; a PM's delegated rights do not extend the application's scope.
4. **Add conservative correlation.** Exact message copies can share a canonical evidence record only after collision checks. Reply headers and known message/request links are strong candidates. Customer identity plus product/PO and semantic request similarity can nominate cross-thread candidates; subject similarity alone cannot merge. Multiple requests in the source email remain distinct. Unknown customer, conflicting entity facts, or ambiguous candidates go to a reviewer. Every accepted merge/split is reversible and audited; internal IDs stay out of email subjects and ordinary screens.
5. **Connect an approved model provider.** Implement the provider adapter against the bounded extraction contract. Treat source text as untrusted evidence. Resolve facts and owners against approved mappings. No model-provided state is committed directly. Review proposals first; enable automatic acceptance only for measured categories with clear evidence and calibrated thresholds. A confidence value alone is not calibration.
6. **Reconcile responses and changes.** Link only the obligations addressed by an observed sent reply. Do not infer customer receipt merely from a draft; record bounce evidence and delivery uncertainty. Updated requests, requirements, dependencies and promises generate new versioned events. Human verification controls final resolution. Keep request-age, response-due and promised-resolution deadlines separate.
7. **Deploy durable jobs.** Five-minute deadline recognition is independent of hourly reconciliation. Add webhook validation and renewal plus delta repair after missed notifications. Use mailbox concurrency limits, leases, bounded backoff, DLQ and an operator-visible coverage state. If sync is stale, surface uncertainty and escalate to the duty owner rather than declaring no outstanding responses.
8. **Attach the real workspace.** Serve the existing API shape from authorized database projections. Add evidence access, updates with version checks, pending review and a department route. Only then remove the fictional-data banner. Test with separate PM, department and president accounts.

## Acceptance path

Use an approved test customer and two independent internal accounts to send a multi-part request, copy it into another mailbox, forward part to QA, answer only one portion, revise the other in a separate thread, and eventually confirm completion with evidence. The system must preserve one identity per issue, correct ownership, the unanswered portion's original clock, all department handoffs and the reviewed closure. The president must see the operational summary without gaining unrestricted mailbox access.

## Automation boundary

Initial pilot has no send adapter or send permission. Drafts may be prepared for human use. Later sending needs separate recipient resolution, approved scope, per-send approval rules, quiet-hour handling, duplicate suppression, stale-draft invalidation, unknown-send recovery and full audit. Quiet hours never pause the underlying 24-hour obligation.
